1. EXECUTIVE SUMMARY & ABSTRACT
================================================================================

Traditional commercial music recommendation platforms (e.g., Spotify, Apple Music,
YouTube Music) predominantly depend on collaborative filtering and user metadata
aggregation—mining user listening histories, playlist co-occurrences, and community
tags. While effective for mainstream, highly-streamed commercial catalogs, this
paradigm suffers from three critical data mining bottlenecks:

  1. The "Cold-Start" Problem: Newly released tracks, independent creators, or
     unindexed audio files with zero listening history cannot be analyzed or
     recommended.
  2. Subjective Metadata Bias: Human-labeled genre tags and moods are qualitative,
     inconsistent, and often inaccurate.
  3. Data Sparsity: Long-tail audio assets lack sufficient interaction matrices
     to produce meaningful collaborative filtering recommendations.

MusicMatch addresses these limitations by implementing a pure content-based audio
data mining and warehousing architecture. Operating directly upon raw acoustic
time-domain waveforms (MP3, WAV, MPEG, AAC, OPUS, WebM, FLAC, and live microphone
recordings), the system:
  * Ingests and standardizes audio through digital signal processing (DSP).
  * Extracts an 18-dimensional acoustic feature vector spanning timbral envelopes
    (13 MFCCs), rhythmic cadence (Tempo BPM), spectral brightness (Spectral Centroid),
    harmonic profile (Chroma STFT), percussive noisiness (Zero-Crossing Rate), and
    dynamic loudness (RMS Energy).
  * Applies Z-score Standard Scaling to normalize disparate numerical magnitudes.
  * Conducts unsupervised cluster discovery using K-Means Partitioning with automated
    hyperparameter optimization via the Elbow Method and Silhouette Analysis.
  * Projects the 18-dimensional manifold into an interactive 2D spatial representation
    using Principal Component Analysis (PCA).
  * Computes high-dimensional Cosine Similarity matrices for intra-catalog retrieval
    and cross-references extracted acoustic signatures against the global Spotify
    Web API catalog.
  * Persists user sessions, acoustic features, and relational models into a managed
    Supabase PostgreSQL warehouse secured by JWT authentication.

3. MATHEMATICAL FOUNDATIONS & FEATURE EXTRACTION
================================================================================

Every audio track is conditioned to single-channel mono at sample rate sr = 22,050 Hz
over a standard 30-second temporal window.

THE 18-DIMENSIONAL ACOUSTIC FEATURE SPACE:
------------------------------------------
1. MFCC 0 to 12 (13 Dimensions):
   Formula: C_n = SUM_{m=1}^{M} [ log(S_m) * cos( (pi * n * (m - 0.5)) / M ) ]
   Role: Mel-Frequency Cepstral Coefficients capture timbral texture, vocal resonance,
   and the spectral envelope through Discrete Cosine Transform over Mel-filterbanks.

2. Tempo BPM (1 Dimension):
   Formula: R_xx(tau) = SUM_n [ x[n] * x[n - tau] ]
   Role: Evaluates onset strength envelope autocorrelation to detect pulse cadence,
   beat periodicity, and danceability.

3. Spectral Centroid (1 Dimension):
   Formula: mu = SUM [ f * S(f) ] / SUM [ S(f) ]
   Role: Spectral center of mass; measures perceived high-frequency brightness vs.
   low-frequency warmth.

4. Chroma STFT Mean (1 Dimension):
   Formula: C_bar = (1 / 12) * SUM_{b=1}^{12} [ Chroma_b ]
   Role: 12-semitone pitch class distribution; represents harmonic content, tonal
   stability, and musical key signature.

5. Zero-Crossing Rate - ZCR (1 Dimension):
   Formula: ZCR = (1 / 2N) * SUM_{n=1}^{N-1} | sgn(x[n]) - sgn(x[n-1]) |
   Role: Rate of signal sign inversions; distinguishes percussive/noisy transients
   from smooth melodic waveforms.

6. RMS Energy (1 Dimension):
   Formula: RMS = SQRT( (1 / N) * SUM_{n=1}^N x[n]^2 )
   Role: Root-mean-square amplitude; quantitative proxy for acoustic loudness,
   dynamic power, and signal intensity.

Z-SCORE NORMALIZATION:
----------------------
Features exhibit disparate raw scales (Centroid: 1000-4000 Hz vs. ZCR: 0.01-0.10).
Unnormalized Euclidean distance calculations would be completely distorted by the
centroid. StandardScaler adjusts each feature column:
  z = (x - mean) / standard_deviation
Resulting in zero mean (mu = 0) and unit variance (sigma^2 = 1) across all dimensions.

4. MACHINE LEARNING & DATA MINING ALGORITHMS
================================================================================

4.1 UNSUPERVISED K-MEANS CLUSTERING:
-----------------------------------
Partitions N audio feature vectors into K disjoint clusters by minimizing the
Within-Cluster Sum of Squares (Inertia):
  J(K) = SUM_{k=1}^K SUM_{x in C_k} || x - mu_k ||^2
Initialized using k-means++ seeding across 10 random restarts (n_init=10,
random_state=42) to ensure deterministic, global convergence.

4.2 AUTOMATIC K SELECTION (AUTO-K):
----------------------------------
  1. The Elbow Method: Evaluates inertia J(K) for K in [2..10]. The optimal knee K*
     is determined by locating the maximum second discrete difference:
     Delta^2 J(K) = J(K+1) - 2*J(K) + J(K-1)
  2. Silhouette Coefficient Analysis: Evaluates intra-cluster tightness a(i)
     against nearest-cluster separation b(i) for each song i:
     s(i) = (b(i) - a(i)) / max(a(i), b(i)), where s(i) in [-1.0, +1.0]
     The partition maximizing mean silhouette score is selected as the recommended K.

4.3 PRINCIPAL COMPONENT ANALYSIS (PCA):
---------------------------------------
Transforms the 18-dimensional scaled matrix Z into an orthogonal 2D visual plane:
  1. Computes covariance matrix Sigma = (1 / N) * Z^T * Z.
  2. Obtains eigenvectors v_1, v_2 corresponding to top two eigenvalues lambda_1, lambda_2.
  3. Projects points into 2D canvas coordinates: Y = Z * [v_1, v_2].
This preserves maximal acoustic variance (74.8%) on the interactive song map.

4.4 CONTENT-BASED SIMILARITY RETRIEVAL:
---------------------------------------
Computes the cosine of the angle between two 18-D vectors u and v:
  CosineSim(u, v) = (u . v) / ( ||u|| * ||v|| )
Translated to an intuitive similarity percentage:
  Match(%) = [ (CosineSim(u, v) + 1) / 2 ] * 100%

5. DATA WAREHOUSING & RELATIONAL SCHEMA (SUPABASE POSTGRESQL)
================================================================================

The cloud data warehouse maintains five core relational tables:

1. USERS:
   - id: BIGSERIAL [PRIMARY KEY]
   - username: TEXT [UNIQUE, NOT NULL]
   - email: TEXT [UNIQUE, NOT NULL]
   - password_hash: TEXT (bcrypt encrypted)
   - created_at: TIMESTAMPTZ

2. SESSIONS:
   - session_id: TEXT [PRIMARY KEY]
   - user_id: BIGINT [FOREIGN KEY -> USERS.id, NULLABLE]
   - created_at: TIMESTAMPTZ
   - updated_at: TIMESTAMPTZ

3. SONGS:
   - id: BIGSERIAL [PRIMARY KEY]
   - session_id: TEXT [FOREIGN KEY -> SESSIONS.session_id]
   - name: TEXT [NOT NULL]
   - features: JSONB (18-dimensional numerical array)
   - tempo: FLOAT8
   - spectral_centroid: FLOAT8
   - chroma_mean: FLOAT8
   - zcr_mean: FLOAT8
   - rms_mean: FLOAT8
   - cluster: INT4
   - pca_x: FLOAT8
   - pca_y: FLOAT8
   - created_at: TIMESTAMPTZ

4. SIMILARITY:
   - session_id: TEXT [PRIMARY KEY, FOREIGN KEY -> SESSIONS.session_id]
   - matrix: JSONB (Precomputed symmetric pairwise N x N similarity matrix)

5. CONTACT_MESSAGES:
   - id: BIGSERIAL [PRIMARY KEY]
   - name: TEXT, email: TEXT, message: TEXT
   - created_at: TIMESTAMPTZ
